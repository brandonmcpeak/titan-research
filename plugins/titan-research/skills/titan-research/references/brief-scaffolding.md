# Brief Scaffolding: File Creation Protocol

Defines the structure, naming, and lifecycle of research brief files.

## Auto-Creation Trigger

Create a brief file automatically when:
- User invokes /titan with a research topic
- User says "deep research", "research this", or equivalent triggers
- Phase 0 begins and no existing brief matches the topic

## File Naming

```
BRIEF_topic-kebab-case_DRAFT_v1_YYYY-MM-DD.md
```

Examples:
- `BRIEF_rag-vs-fine-tuning_DRAFT_v1_2026-04-08.md`
- `BRIEF_market-entry-japan_DRAFT_v1_2026-04-08.md`

Status transitions reflected in filename:
- `DRAFT`: initial creation, sections being filled
- `VALIDATED`: all DOR quality gates passed
- `TITAN-READY`: approved by user, research launching
- `RESEARCH-COMPLETE`: associated report delivered

On status change, rename file: `BRIEF_topic_VALIDATED_v1_YYYY-MM-DD.md`

## File Location

Save briefs to: `resources/research/briefs/`

Create the directory if it does not exist.

## YAML Front Matter

```yaml
---
type: RESEARCH_BRIEF
status: Draft
topic: topic-kebab-case
topic_area: [spirituality | business | technology | operations | career | finance | health]
date: YYYY-MM-DD
version: 1.0
titan_ready: false
dor_quality_gates_passed: false
research_completed: false
research_report: null
tags: [tag1, tag2]
source: titan-research
---
```

Update lifecycle fields as the brief progresses:
- `titan_ready: true` when user approves launch
- `dor_quality_gates_passed: true` when all gates clear
- `research_completed: true` when report is delivered
- `research_report: RESEARCH_REPORT_topic_v1_YYYY-MM-DD.md` when report exists

## Lifecycle Flow

```
Draft -> Validated -> Titan-Ready -> Research-Complete
  |         |            |              |
  |         |            |              +-- Report delivered, brief archived
  |         |            +-- User approved, research launching
  |         +-- All DOR quality gates passed
  +-- Sections being filled via facilitation
```

## Section Rules

- "Optional" sections (Hypothesis, Source Preferences, Divergence Requirements) are
  only optional if genuinely not applicable. The facilitator should still ask.
- Claude Working Notes: always populated. This is where Claude tracks internal state.
- Core Question and Success Criteria are NEVER optional.

## Edge Cases

**Vague topic, no clear question:**
- Create brief with topic in title, leave Core Question blank
- Enter full facilitation mode to extract the real question
- Do not proceed past Draft until Core Question is filled

**User provides a complete brief:**
- Map their content to the template sections
- Validate against DOR quality gates
- Skip to Validated status if gates pass
- Ask only about missing sections

**Express mode:**
- Create brief with Core Question filled, all other sections marked "[Express mode]"
- Set `titan_ready: true`, `dor_quality_gates_passed: false`
- Note in Claude Working Notes: "Express mode; abbreviated brief"

**Existing brief for same topic:**
- Check for existing briefs before creating
- If found, ask user: update existing or create new version?
- New version: increment version number in filename
